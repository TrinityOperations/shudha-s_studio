# Decisions log

Append one dated line per non-obvious choice. Newest at the bottom.

- 2026-10-02: Stack chosen: Next.js 15 + Supabase + Drizzle + Tailwind/shadcn, hosted on Vercel. Reason: free at this scale, one codebase for site and dashboard, strong SEO via server rendering.
- 2026-10-02: v1 extras confirmed: custom order wizard, English/Bengali toggle, wishlist, customer gallery, PWA dashboard with push, seasonal theming. Everything else in SRS section 5 is deferred.
- 2026-10-02: No prices or payments in v1. Every order is quoted during the appointment.
- 2026-10-03: Booking engine is custom (not Cal.com embed) to keep the brand look and attach the custom-order brief to each booking.
- 2026-10-03: Supabase region Sydney (ap-southeast-2) for latency and data residency.
- 2026-10-03: Wishlist stored in the browser (no customer accounts in v1).
- 2026-10-04: Hosting moved from Vercel to Netlify. Vercel's free Hobby plan can't deploy private organisation repos and is limited to non-commercial use; Netlify's free plan allows both. Analytics: Umami instead of Vercel Analytics.
- 2026-10-04: Supabase free plan pauses inactive projects; add a scheduled keep-alive ping before launch, or the client moves to a paid plan.
- 2026-10-04: Next.js 16 (16.3.8) instead of 15: `create-next-app` installs 16, 15 is in maintenance, and 16 is what Netlify's current runtime targets. Consequences: `src/proxy.ts` instead of `middleware.ts`, Turbopack, async-only request APIs, ESLint run directly. CLAUDE.md updated.
- 2026-10-04: shadcn/ui v4 with the default `base-nova` style (Base UI primitives, not Radix). Forms use the `Field*` components with React Hook Form; v4 has no `Form` wrapper.
- 2026-10-04: Zod validation messages are i18n keys, so one schema serves client and server and every error is translatable. The client renders `t(error.message)` via `FieldMessage`.
- 2026-10-04: i18n is a flat-key JSON dictionary with a cookie-persisted locale and per-key Bengali → English fallback. No i18n routing (`/bn/...`) because the content is the same page in two languages and SEO targets English.
- 2026-10-04: Admin identity is "signed in with Supabase and email equals OWNER_EMAIL (case-insensitive)". No users table until OD-05 (helper roles) is wanted. Checked in proxy.ts, in every admin layout/page, and in every admin action.
- 2026-10-04: Row Level Security enabled on every table with no policies. The app reaches Postgres through Drizzle as the table owner; the anon key can only do Auth. Supabase's REST API is intentionally unusable for data.
- 2026-10-04: Overlapping bookings are prevented by a Postgres EXCLUDE constraint on `tstzrange(starts_at, ends_at)` for non-cancelled rows, written in a custom migration because Drizzle has no EXCLUDE builder. `drizzle-kit generate` diffs against its own snapshot, so it will not try to drop it; never use `drizzle-kit push`.
- 2026-10-04: Storage buckets: `product-images`, `site-images`, `gallery-images` (public), `gallery-pending`, `booking-uploads` (private). Customer gallery photos land in `gallery-pending` and are copied to `gallery-images` on approval.
- 2026-10-04: Bengali content is stored in sibling `_bn` columns rather than a translations table. Simpler queries and search; the owner edits both in one form (OD-36).
- 2026-10-04: Site-wide content (OD-30, OD-33, OD-35) is a `site_settings` key/jsonb table with one Zod schema per key, so adding a content block needs no migration.
- 2026-10-04: Seeded categories (Mugs, Apparel, Home decor, Keyrings, Cushions, Stationery, Gift packs) and occasions (Birthday, Anniversary, Wedding, Eid, Corporate, Baby, Graduation) are provisional until the client meeting (SRS §9). The seed is idempotent and never overwrites edits.
- 2026-10-04: `DIRECT_DATABASE_URL` (Supabase session pooler, port 5432) is used only by drizzle-kit; the app uses the transaction pooler in `DATABASE_URL` with `prepare: false`.
- 2026-10-04: Turnstile is on the admin login form too, because it is a public form (PW-38). Cloudflare's always-pass test keys are used locally and in e2e.
- 2026-10-04: Node 24 pinned in `.nvmrc` (current LTS, matches the dev machines and Netlify).
- 2026-10-05: `sharp` added for product image processing (resize to 1600px + 400px thumbnail, webp). It is the standard Node image library and Next.js already depends on it.
- 2026-10-05: `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities` added for image reordering (OD-11 asks for drag and drop). dnd-kit ships a keyboard sensor with screen-reader announcements, which is the hard part of accessible drag and drop. Category and occasion reordering uses move up/down buttons instead: short lists, no dependency needed.
- 2026-10-05: Images are downscaled in the browser before upload (longest side 2000px; PNG stays PNG for transparency, everything else becomes JPEG; files under 1.5 MB and 2000px are sent untouched). Reason: Netlify's synchronous function body limit is 6 MB, so a raw 10 MB phone photo can't reach a server action in production. The server still validates type and size and re-encodes with sharp. `experimental.serverActions.bodySizeLimit` is 12 MB.
- 2026-10-05: Personalisation options (OD-14) are a fixed list of eight keys in `PERSONALISATION_OPTIONS` (validators/products.ts) with i18n labels; anything else goes in the free-text notes. The list is one array so it can change after the client meeting.
- 2026-10-05: Deleting a product removes its storage objects first, then the row; if storage removal fails nothing is deleted. Same for bulk delete and single image delete. Orphan files are worse to clean up than a retry.
- 2026-10-05: Tags created inline from the product form are kept even if later unused; the owner deletes them from the taxonomy page. Renaming a category, occasion or tag never changes its slug so public URLs stay stable.
- 2026-10-05: Product status transitions: publishedAt is set the first time a product is published and never reset. Archived products return to draft on unarchive. Bulk publish touches drafts only, bulk unpublish published only, bulk archive anything not archived.
- 2026-10-05: Database driver switched from `postgres` (postgres.js) to `pg` (node-postgres) via `drizzle-orm/node-postgres`. postgres.js pipelines queries onto busy sockets once the pool is full, which Supabase's transaction pooler (port 6543) cannot handle: the queued queries never get a reply and the request hangs (seen when saving a product re-renders the edit page; see porsager/postgres#970). Its `max_pipeline: 0` escape hatch breaks `sql.begin` in 3.4.9 (porsager/postgres#1189). `pg` queues excess queries client-side instead. The pool is 10 per process by default and configurable with `DB_POOL_MAX` for Netlify, where each function instance has its own pool. TLS is verified (`rejectUnauthorized: true`) against Supabase's root CA, committed at `certs/supabase-ca.crt` (public certificate, not a secret; expires April 2031) and read once at startup; a missing file throws rather than falling back to an unverified connection. drizzle-kit still uses `DIRECT_DATABASE_URL` and now picks up `pg` as its driver, with the same verified `ssl` object. `drizzle.config.ts` splits the URL into host/port/user/password/database because drizzle-kit silently ignores `ssl` when `dbCredentials.url` is set. The Supabase project enforces SSL, so unencrypted connections to either pooler are refused (`ESSLREQUIRED`).
- 2026-10-07: SRS v1.0 after the client meeting on 5 Oct. Replaces the 2026-10-02 "no prices" decision: products get an optional starting price, `products.price_from` (nullable integer, whole AUD dollars, check >= 0), shown as "From $X" and hidden when blank. Still no cart, checkout or payments. Added in slice #3 with one migration.
- 2026-10-07: WhatsApp is the client's main channel. We use click-to-chat `wa.me` links only (public chat button, owner one-tap reply, links in emails). No WhatsApp Business Platform API: it needs Meta business verification and approved templates, can cost per message, and is overkill at this size. `bookings.customer_phone` holds the WhatsApp number, so no new column. Links are built only by `src/lib/whatsapp.ts`; numbers are validated and stored normalised (international digits, no `+`) by `whatsappNumberSchema`. Local numbers are assumed Australian.
- 2026-10-07: Delivery (pickup or post Australia-wide) is arranged during the consultation. The site only shows a delivery note; there are no delivery fields, costs or tracking.
- 2026-10-07: Business orders are captured in the wizard brief (`CustomOrderBrief.orderFor`, `businessName`). The brief is jsonb, so no migration.
- 2026-10-07: Seed categories and occasions updated to the client's range (adds Chocolate wrappers, Nameplates, Cards, Posters, Christmas, New Year; Stationery replaced by Cards and Posters). The seed still never overwrites or deletes existing rows, so existing databases keep Stationery until the owner removes it.
- 2026-10-08: i18n key convention: public pages use `<section>.*`, dashboard screens use `admin.<section>.*` (as built in #2), shared words `common.*`, validation messages `errors.*`. `en.json` and `bn.json` are sorted by key once here; new keys go in alphabetical position.
